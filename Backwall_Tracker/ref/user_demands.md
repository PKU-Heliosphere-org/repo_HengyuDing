# 后墙（Backwall Tracker）开发需求

---

## 1. 总体需求概述
课题组在研制载荷时，经常需要准备报告材料，参加评审会议，还需要制定严格的研制计划，并按照计划执行。为了更好地管理研制过程中的各项任务，课题组希望开发一个“后墙（Backwall Tracker）”系统，用于跟踪和管理研制任务的进展情况，从而提高研制效率和质量，确保各项任务按时完成。

## 2. 初样功能需求
```
flowchart TD
    A["建立项目与硬里程碑"] --> B["倒排研制任务"]
    B --> C["责任人每日记录进展"]
    C --> D["系统计算延期风险"]
    D --> E["临期提醒与升级通知"]
    E --> F["完成闭环"]

    G["会议表图片"] --> H["OCR与大模型提取"]
    I["会议纪要 PDF"] --> H
    H --> J["人工核对"]
    J --> B
```

### 2.1 建立项目与硬里程碑
用户可以创建新的研制项目，并为每个项目设置关键的硬里程碑。具体需要实现的功能包括：
- 新建任务、子任务和依赖关系；
- 指定负责人、协作人、计划起止时间；
- 记录实际进度、阻塞原因和下一步工作；
- 显示里程碑倒计时和延期风险；
- 区分“原计划”和“当前调整计划”。

任务状态建议统一为：未开始 → 进行中 → 待提交 → 待确认 → 已闭环。

### 2.2 “今日”页面
这是使用频率最高的页面，重点追求三十秒内完成记录：

今天必须完成；
三天内到期；
已经逾期；
等待他人确认；
当前被阻塞；
一句话记录“今天完成了什么”；
上传照片、PDF或其他附件。

### 2.3 导入下周会议表图片
手机拍照/上传图片 → 图像裁剪、纠偏和增强 → OCR 识别 → 大模型整理为结构化会议 → 人工核对 → 写入会议安排。

建议提取以下字段：
会议名称；
日期和时间；
地点或会议链接；
参加人员；
汇报人；
汇报材料截止时间。

### 2.4 导入会议纪要 PDF
上传 PDF → 判断文字版或扫描版 → 提取正文/OCR→ 大模型识别行动项 → 人工生成责任人与日期 → 生成闭环任务

每条闭环任务至少包含：

会议名称及日期；
专家意见或会议要求原文；
责任人；
配合人员；
计划完成日期；
需要提交的文件；
审核或确认人；
原始PDF页码；
当前闭环状态。

### 2.5 临期提醒

采用分层提醒：

| 时间    | 提醒对象      | 内容      |
| ----- | --------- | ------- |
| 截止前7天 | 责任人       | 提前准备    |
| 截止前3天 | 责任人、协作人   | 进入临期    |
| 截止前1天 | 责任人、协作人       | 强提醒     |
| 逾期当天  | 责任人、协作人、项目管理员 | 已逾期     |
| 持续逾期  | 负责人、协作人、项目管理员 | 每日提醒或升级 |

## 3. 其他需求
1. 后端用python开发，前端用Vue3开发，数据库用PostgreSQL。后端框架建议使用FastAPI，前端框架建议使用Vite+Vue3+ElementPlus。
2. 本项目部署在校园网服务器内。用户可通过浏览器直接访问WebUI界面（http://162.105.246.14:给定端口）。WebUI界面应支持移动端访问，适配手机和平板电脑；也应支持桌面端访问，适配不同分辨率的显示器。
3. 系统应支持多用户登录，用户角色包括：普通用户、项目管理员、系统管理员。
4. 支持大模型接口调用，能够处理会议表图片和会议纪要 PDF 的识别与解析。需要预留API配置文件。
5. 系统应提供数据导出功能，例如本周工作，以便于在周报上存档。
6. （重要！）便携性记录、便携性浏览、格式清晰明了。
