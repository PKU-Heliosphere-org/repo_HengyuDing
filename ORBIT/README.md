# ORBIT

Orbit Rendering & Basic Interaction Toolkit：轨道数据可视化与交互分析工具。

当前版本 **v0.3（0.3.0）**，版本日期 **2026-11-12**。采用本地 Python/FastAPI + NumPy/Astropy/SPICE 后端、React/TypeScript + Three.js 界面，支持 CSV / XLSX 星历表回放、自由三维视角和八大行星图层。

v0.3 包含当前完整功能状态：可调整时间轴、渐细尾迹、按内层光晕定义的 6px 默认光点、行星默认尾迹、100 AU 固定曲线显示范围、极坐标参考平面、默认星空，以及先缓存再播放的区间渲染。版本变化见 [更新记录](CHANGELOG.md)，具体使用方式见下文。

## 启动

在 PowerShell 中进入 `ORBIT/`：

```powershell
.\scripts\start.ps1
```

脚本会自动打开独立的 ORBIT 桌面窗口，无浏览器地址栏或标签栏。关闭窗口即停止本次启动的服务，关闭前请保存项目文件。默认自动选择空闲本地端口，不占用其他已运行会话；可用 `-Port 8877` 指定端口。

桌面窗口使用 pywebview + Microsoft Edge WebView2 Runtime，Windows 10/11 通常已安装后者；缺少时请安装 [WebView2 Evergreen Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。项目保存与 PNG 导出弹出系统保存对话框。窗口缓存位于 `.cache/webview2/`，不作为项目存储；继续通过“保存项目”保留工作。

若希望使用浏览器或运行浏览器测试：

```powershell
.\scripts\start.ps1 -Browser -Port 8877
```

自动打开 <http://127.0.0.1:8877>，按 Ctrl+C 停止服务。`-Browser` 未指定端口时使用 8765；`-OpenBrowser` 保留为兼容入口。升级后请先保存原会话，再重启服务加载新版后端。

新环境需要 Python 3.11+、Node.js 22.13+ 和 WebView2 Runtime（浏览器模式需要支持 WebGL2 的桌面浏览器）：

```powershell
.\scripts\setup.ps1
.\scripts\start.ps1
```

安装会下载依赖和约 33 MB 的 JPL/NAIF 星历；之后可离线运行。Python 环境位于 `.venv/`，前端依赖位于 `frontend/node_modules/`。若已有 v0.1 环境，可运行：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".\backend[test]"
.\.venv\Scripts\python.exe scripts\fetch_ephemeris.py
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

已有 v0.2 环境升级到 v0.3 时，先保存项目并关闭原窗口。沿用已有依赖和本地星历，更新后端包信息并重新构建前端：

```powershell
.\.venv\Scripts\python.exe -m pip install --no-deps --no-build-isolation -e backend
Set-Location frontend
npm run build
Set-Location ..
.\scripts\start.ps1
```

若本机策略禁止 PowerShell 脚本，可从 `ORBIT/` 直接启动桌面窗口：

```powershell
.\.venv\Scripts\python.exe -m orbit.desktop
```

保留纯服务入口，供前端开发或自动化检查使用：

```powershell
.\.venv\Scripts\python.exe -m uvicorn orbit.app:app --host 127.0.0.1 --port 8765
```

## 行星和视角

1. 点击“添加行星”，选择八大行星中的一个或多个，添加后默认显示尾迹。空场景可设置太阳/地球中心、J2000 赤道系/J2000 黄道系及初始 UTC；已有场景沿用其中心和参考系。
2. 远处显示对应颜色的发光点；靠近时平滑切换为真实尺寸的纹理球体。选择行星后点击“聚焦表面”可直接观察近景。土星包含环。
3. 鼠标左键拖动可自由旋转、翻越极点并倒置画面；滚轮缩放，右键拖动平移。工具栏提供标准视角、恢复总览、聚焦、跟随和左右滚转。
4. 聚焦行星后会跟随其位置，保持当前观察方向；播放时间和调整窗口尺寸不会重置视角。可关闭跟随，或切换总览。
5. 地球使用昼夜两张纹理，可开启零度经线；日照方向、自转和经线与全局时间同步。其他行星使用连续的明暗过渡。星空背景默认开启，可在工具栏关闭；恢复项目时沿用已保存的开关。参考平面采用同心圆和每隔 30° 的径向线绘制极坐标网格。
6. 行星与 CSV 图层统一提供“轨道、尾迹、标签”开关。行星“轨道”使用当前日心位置和速度计算瞬时密切椭圆，遍历真近点角绘制闭合曲线；地心场景中平移显示。它随时间更新，不代表未来实际星历路径。“尾迹”使用过去的真实星历位置，时长由底部菜单设置（1–365 天），不会绘制未来路径。
7. 属性面板可调各对象光点大小（2–48 px，步长 0.1，默认 6；尺寸指内层光晕直径，外层光晕直径约为其 4.55 倍）与各类轨道线宽（0.5–8 px，默认 1，含密切曲线）。尾迹独立于轨道线宽：头部宽度为光点大小的一半（默认 3px），按历史时间向尾端逐渐收细至零并变暗，缩放视角时保持屏幕像素宽度。底部“尾迹时长”表示当前时刻之前的时间长度，并非固定空间长度；数据不足时只显示已有历史，缺测处保持断开。设置随项目保存；已有项目的明确数值继续保留，缺省字段采用新默认值。光点大小不改变行星真实表面半径。

行星尺寸和空间距离使用真实比例；发光点属于远距离可见性增强。近景太阳光为几何方向，未模拟食、折射、大气散射、云层或地形。

## 星历表导入和项目

1. 导入 UTF-8 CSV 或 XLSX，或使用本地“打开样例”。多工作表 XLSX 先选择一个工作表再读取；每个工作表可分别导入为独立对象。指定列映射、对象名、中心天体、参考系、历元来源、时间体系和单位。
2. 运行预检，处理重复项和冲突行，再添加到场景。预检与选行不会修改源文件；XLSX 的错误、冲突和排除行号均对应实际工作表行号。
3. 时间轴可回放、拖动、跳转采样；空格播放/暂停。拖动时间轴上沿分隔条可上下调整面板高度，双击恢复默认；分隔条获得键盘焦点后可用上下方向键调整，Home/End 收至最小/展开至最大，三维画布始终保留至少 250px 高度。“密切轨道”显示所选采样的圆锥曲线，“编辑参数”产生独立静态假设图层。
4. “保存项目”下载 `.orbit.json`，包括原始 CSV / XLSX 内容、所选工作表、清洗决策、图层、时间、视角和跟随状态。“打开项目”可在服务重启后恢复，不再依赖原文件路径。也支持仅含行星的项目和 PNG 导出。

v0.3 的软件版本号为 0.3.0；项目格式仍写入 `schema_version=2`，兼容读取格式 1 和 2。软件版本升级不改变项目格式编号。星历和纹理不嵌入项目文件，接收项目的机器需先完成本地安装。

时间轴上方可勾选“启用缓存渲染”，拖动双端滑块选择需要播放的时间范围。软件会先准备整个范围内的行星位置、速度和姿态，并补齐起点之前所需的尾迹历史；进度完成、显示“缓存就绪”后，播放按钮才可用。播放和时间游标限制在所选范围内，到终点停止，再次播放从所选起点开始。区间内播放无需继续请求星历，尾迹随时间实时更新，视角仍可自由调整。

修改缓存范围、行星集合、场景坐标声明或尾迹时长会暂停播放并重新准备；修改播放倍率和外观不需重算。关闭勾选可中止后续准备、释放缓存并返回普通预览；失败时可“重新准备”。缓存使用本次会话内存，不保存进项目文件；导入对象继续使用已经加载的采样数据，不新增动力学传播。为限制内存，缓存最多容纳 50 万个行星采样，超过时需缩短范围或减少行星。所选播放区间按至多一小时采样，额外历史段按至多六小时采样，采样之间沿用 Hermite 位置插值和 SLERP 姿态插值。

导入对象仍只回放采样数据、进行显示插值和静态圆锥曲线计算，**不进行轨道时间传播**；不在不同中心或参考系的数据之间自动转换。超过允许插值间隔或数据覆盖范围时不外推。密切轨道和参数预览曲线的显示截断半径固定为 100 AU，不提供界面设置，也不沿用旧项目中的半径设置；此范围不改变原始轨迹数据。

XLSX 使用第一条非空行作为表头，支持原生数值、日期时间单元格和 ISO 时间文本；时间体系仍由导入面板指定，不从 Excel 格式猜测 UTC/TT/TDB。纯数字日期序号应先设为 Excel 日期时间单元格，或转成 ISO 文本；需要亚毫秒精度时建议使用 ISO 文本。支持 1900/1904 两种 Excel 日期系统。

公式读取文件已保存的缓存结果，不运行或重新计算公式，预检会提示确认源文件已计算保存；无缓存结果会给出单元格位置并要求重新保存或粘贴为值。无公式工作表只扫描一遍数据。旧版 `.xls` 请先另存为 `.xlsx`，无需本机安装 Excel。

单个导入结果最多 100,000 条、20 MiB（按规范 CSV 文本计量）。源文件可上传至 200 MiB、100 万条；XLSX 最多 256 列，解压总量最多 512 MiB。超过直接导入容量时，先声明时间列和时间体系，再在“时间范围与分辨率”中选择起止时间或目标采样间隔（秒），两者可组合，点击“应用范围与采样”。处理后仍超限可继续调整，每次都从原始上传副本重新处理。

范围筛选包含起止时刻。降采样按连续时间分桶，每桶保留最早时刻的原始记录及同刻冲突记录，不插值或平均；指定起点时按起点对齐，未指定时按首条符合范围记录所在日期的零点对齐。源表行号保留，之后仍需运行预检。处理不会写回原始 CSV/XLSX；项目包含原始文件及筛选设置，恢复时重新应用。项目文件上限为 512 MiB。

“应用范围与采样”使用后台任务，左侧显示进度条，右侧显示“已扫描 xx 条 / 共 xx 条”。CSV 会先统计总条数；XLSX 总条数可能先使用工作表估计值，结束时按实际数据校准，整理结果期间进度不会提前达到 100%。点击“取消处理”可停止扫描并丢弃未完成结果，保留上传副本、筛选设置及上次已应用结果，随后可调整并重试；原始文件不变。

本地参考样例按用户确认采用太阳中心、暂按 J2000 赤道面，保留待核实标记。样例的冲突行选择只是导入决策，并非物理正确性判断。

## 数据模型与精度

- CSV、XLSX 支持六根数或位置/速度两种输入。自动识别 `x/y/z/vx/vy/vz`、`Position X (km)`、`VX (km/sec)`、`x_km/vx_km_s` 等常见表头，也支持手动映射；同时检测到两套字段时必须选择使用哪套。六根数缩写支持 `t/a/e/i/om/w/ta/ma`。
- 坐标输入需明确声明中心天体、J2000 赤道面或黄道面、UTC/TT/TDB、位置单位 km/m/AU 与速度单位 km/s、m/s、AU/day 或 AU/s。不根据数值猜测参考系，也不将地固坐标当作惯性坐标。表头单位与选择不符时必须修正或明确覆盖。
- 缺少完整速度时默认拒绝导入；用户可明确选择“差分生成速度”。先按用户决策处理重复、冲突和排序，再按连续 TAI 秒数作非等间隔三点差分，端点使用单边差分；两点片段使用割线，不跨越缺测间隔，单点片段不可生成。估计误差及生成方法写入警告和日志，不进行轨道传播。
- 每个采样在内部统一保存 `position_km` 和 `velocity_km_s` 两个三分量向量、时间和来源行号，六根数输入先转换，状态向量输入直接保留。界面需要时从向量计算六根数；圆轨道/赤道轨道采用等价角度约定，径向退化或接近抛物线时保留向量并禁用六根数编辑。项目保存原始文件和输入类型、速度来源等导入决策，恢复时重新计算；兼容旧六根数项目。

- 本地使用 JPL `de440s.bsp` 和 NAIF `pck00011.tpc`，存于 `data/ephemeris/`；下载脚本生成来源和 SHA-256 清单。运行期间不访问星历网络服务。重新下载可单独执行 `scripts/fetch_ephemeris.py`。
- 行星支持 1972-01-01 至 2150-01-01 UTC。位置为同一时刻的几何位置，不含光行时和像差修正。水星、金星和地球使用行星中心；火星、木星、土星、天王星和海王星使用对应系统质心近似行星中心，界面有说明。
- 实时窗口按至多一小时采样返回位置、速度和姿态；前端使用三次 Hermite 位置插值、四元数 SLERP 姿态插值，不在缓存窗口外外推。快速播放时会预取，缓冲未就绪时等待。尾迹另行按时长读取历史窗口，长时段自适应加大步长，受本地星历起始日期限制。
- 地球使用 IAU 2006/2000A 与本地 IERS 的 UT1、极移计算姿态，区分观测值、预测值和近似值。超出覆盖时采用 UT1≈UTC、极移为零，界面显示精度限制；未来 UTC 使用当前已知闰秒表。
- 其他行星使用 PCK 中的 IAU 名义定向模型，属于可视化近似。地球纹理中央对应零度经线，东经方向、极轴和太阳光照使用同一姿态变换。
- 时间内部使用连续 TAI 秒；坐标参考历元与数据历元分开显示。高精度测绘、任务导航和长期地球定向预测需更精细的数据与模型。

数据来源：[JPL 星历](https://ssd.jpl.nasa.gov/planets/eph_export.html)、[NAIF PCK](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/pck/pck00011.tpc)、[Astropy IERS](https://docs.astropy.org/en/stable/utils/iers.html)。纹理由用户提供于 `textures/`。

## 检查与开发

```powershell
.\scripts\check.ps1
```

浏览器检查需先在另一终端启动独立测试服务（`scripts/start.ps1 -Browser -Port 8877`），再执行：

```powershell
.\scripts\check.ps1 -Browser -Port 8877
```

测试服务的端口需与参数一致；首次浏览器检查下载 Chromium 到 `.cache/`。性能检查会导入合成数据，建议只对独立测试服务运行：

```powershell
Set-Location frontend
$env:ORBIT_TEST_URL = 'http://127.0.0.1:8877'
node tests/benchmark.mjs --hardware
```

省略 `--hardware` 使用 SwiftShader。开发时在 `ORBIT/` 启动后端，在 `frontend/` 运行 `npm run dev`；API 文档位于 `/docs`。依赖锁定见 `frontend/package-lock.json`、`backend/requirements-lock.txt`。

全部开发文件位于 `ORBIT/`。缓存、星历下载、VS Code 配置、虚拟环境和 `codex/` 由本目录 `.gitignore` 排除。参考样例在 `codex/examples/`，不随新克隆提供；依赖参考样例的测试在缺文件时跳过。
